# Use Cases — Module 09: Prompt Engineering

## Case 1 — JSON Screening

**Scenario:** An API needs to classify tickets and return priority, category and action in JSON.

**Suggested architecture:** Prompt with explicit schema, few examples and response validation in the application.

**Why this choice makes sense:** Integration depends more on structural predictability than creativity.

**Associated exam trap:** Asking for free text and trying to correct it later.

## Case 2 — Assistant with institutional tone

**Scenario:** The company wants the assistant to respond with a professional and concise tone.

**Suggested architecture:** Role prompt, few-shot examples, and clear style boundaries.

**Why this choice makes sense:** Desired behavior can be strongly influenced by instruction and examples.

**Associated exam trap:** Jumping straight to fine-tuning without testing prompt engineering.
